1. Consolidate Billing Webhook Pipeline & State Transitions

convex/billing/webhooks.ts, convex/billing/lifecycle.ts, convex/authed/billing.ts

Strong ports & adapters

Before: Shallow Parsing & Scattered Handlers

http.ts → webhooks.ts
↳ inline signature verification
↳ scattered payload type narrowing
↳ direct DB writes in webhook router

After: Deep Billing Domain Module

BillingDomain (Deep Module)
↳ Verified Svix Adapter
↳ Pure Plan Lifecycles (lifecycle.ts)
↳ Deterministic Database Seam
Problem

Webhook verification and event dispatching leak HTTP header handling concerns straight into Convex mutation logic, reducing test locality.

Solution

Encapsulate all Polar signature verification and event parsing behind a single unified adapter interface inside `convex/billing/provider.ts`.

Wins
  • Tests hit a single verified webhook ingestion interface
  • Webhook retry logic and idempotency decoupled from HTTP transport
  • Clear separation between pure lifecycle mapping and DB writes

Problem

Validation is split across multiple procedural helper functions in `validation.ts` without a unified compilation pass.

Solution

Group validation rules into a single Effect-driven validation service that returns structured typed validation errors.

Wins
  • Atomic error reporting across all prompt fields
  • Better locality for prompt rule enforcement
  • Simpler testing interface for prompt creation limits
